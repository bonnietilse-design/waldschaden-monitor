# Waldschaden-Monitor NRW

**Conifer forest loss in North Rhine-Westphalia since 2017 – a Python/ArcPy pipeline, written with AI**

This repository holds the code behind the StoryMap
**[Vibe coding in ArcGIS: an NRW case study](LINK-TO-STORYMAP)**.
It quantifies the loss of conifer forest per municipality since 2017, analyses where
new damage appeared between 2023 and 2025, and publishes the results to ArcGIS Online.

> **About the code:** all Python code in this repository was generated by an AI model
> (Claude, Anthropic) from my instructions. My part was to define the analysis, run and
> test every script (first on one district, then on all of NRW), check every result in
> ArcGIS Pro, report errors and decide on the fixes, and interpret the results.
> The StoryMap evaluates how well that worked.

## Key results

| | |
|---|---|
| Conifer forest dead or cleared since June 2017 | **139,700 ha – 41 %** of NRW's conifer forest (status Aug 2025) |
| Damaged by September 2023 | 132,700 ha (95 % of all damage) |
| New damage Sept 2023 → Aug 2025 | 7,800 ha |
| Most affected municipality | Burbach (Siegen-Wittgenstein): 87 % |
| Healthy spruce left (assessed area) | 80,300 ha |
| Early symptoms in 2023 → dead or cleared by 2025 | 14.9 % (healthy-looking forest: 2.9 %) – **5.1× the risk** |
| Hotspot of new damage | high Sauerland (Hochsauerlandkreis, Olpe, Siegen-Wittgenstein) |
| Loss by elevation | highest at 200–500 m (56–59 %); new damage rises with altitude, from ~5 % to 7 % at 700–800 m |
| Loss by slope direction | south/south-east 48 % vs. north 44 % (NRW); 76 % vs. 61 % in the Märkischer Kreis |

## Pipeline

Run the scripts in this order with the **ArcGIS Pro Python environment** (`arcgispro-py3`).
Each step writes a CSV report to `DATA_DIR\reports`.

| Step | Script | What it does | Main output | Runtime (NRW) |
|---|---|---|---|---|
| 00a | `00a_download_vitalitaet.py` | Downloads the vitality data from OpenGeodata.NRW with resume, size check and zip test | unzipped shapefiles | network-dependent |
| 00b | `00b_check_shapefile.py` | Diagnostic: checks a zip and its .shp/.shx/.dbf for truncation (no ArcGIS needed) | console report | seconds |
| 01 | `01_import_vitalitaet.py` | Imports all releases and the species raster into one file geodatabase, names them by date (`VA_2025_08` …), adds aliases and coded value domains | `Waldschaden_NRW_Rohdaten.gdb` | long (large files) |
| 02 | `02_import_grenzen.py` | Imports the DVG2 boundaries and checks the counts | `Gemeinden` (396), `Kreise` (53), `NRW_Grenze` | < 1 min |
| 03 | `03_inspect.py` | Checks the data: hectares per class and release, Schadstufe × Schad_agg cross table, image dates, species raster values, boundaries | `03_inspect_*.csv` | 5–15 min |
| 03b | `03b_species_check.py` | Overlays the species raster with the damage classes of the test district – used to derive the species legend | console table | ~1 min (test) |
| 04 | `04_clip.py` | Intersects each release with the municipalities; every polygon gets its municipality and district key; checks that all releases have the same total area | `VA_<release>_<TAG>` | 2.5 h |
| 05 | `05_stats.py` | Damage statistics per municipality and district for each release | `Stats_Gemeinden_*`, `Stats_Kreise_*`, `05_stats_*.csv` | 1 min |
| 06 | `06_change.py` | Rasterises the releases (10 m), combines them, dates the damage, runs the early-warning test | `Schad_*`, `Schadensjahr_*`, `06_change_*.csv` | 3–10 min |
| 07 | `07_species.py` | Species × damage class, healthy spruce left, spruce fields per municipality | `07_species_*.csv`, fields in `Stats_Gemeinden_*` | 4 min |
| 08 | `08_hotspots.py` | 1 km² hexagons, damage per hexagon, Optimized Hot Spot Analysis (Getis-Ord Gi*) for damage share, new damage and early symptoms | `Hex_*`, `HS_*` | test district: 5 min |
| 08b | `08b_terrain.py` | Mosaics and projects the Copernicus DEM, derives 100 m elevation bands and slope direction, and compares loss and new damage across them (shares, not hectares); writes two charts | `DEM_*`, `Hoehenstufe_*`, `Exposition_*`, `08b_*.csv`, `08b_*.png` | ~2 min (test) |
| 09a | `09a_prepare_publish.py` | Builds a lean publish geodatabase and estimates the ArcGIS Online credit cost – uploads nothing | `Waldschaden_NRW_Publish.gdb` | seconds |
| 09b | `09b_publish.py` | Publishes it as one hosted feature layer (ArcGIS API for Python, Pro sign-in) – private by default | hosted feature layer | < 1 min |

The damage polygons (5 million features) and the `Schadensjahr` raster were published separately as
**vector and raster tile layers**, created in ArcGIS Pro (*Create Vector Tile Package*, *Create Map Tile Package*):
190 MB and 21 MB, a fraction of the cost of hosted feature layers.

## Setup

1. **Requirements:** ArcGIS Pro 3.x with Spatial Analyst (steps 03b, 06–08b) and the `arcgis` package
   (included in `arcgispro-py3`, step 09b). Step 00b runs with plain Python.
2. **Data:** download from OpenGeodata.NRW (see *Data* below), or use `00a_download_vitalitaet.py`.
   For step 08b, download the Copernicus DEM GLO-30 for NRW (e.g. from OpenTopography as one GeoTIFF)
   and set `DEM_DIR` at the top of `08b_terrain.py`.
3. **Paths:** steps 00a–02 have their settings at the top of each script.
   From step 03 on, **all settings are in `config.py`**: paths, releases, damage definitions, species legend.
4. **Test first:** `RUN_MODE = "test"` in `config.py` runs steps 04–08 on one district
   (`TEST_KREIS_KN = "05962"`, Märkischer Kreis) in minutes. Switch to `RUN_MODE = "nrw"` for all of NRW.
   Output names end in `_KN05962` or `_NRW`, so test and full results never overwrite each other.

## Definitions

- **Damaged** = `Schad_agg` 2 (standing dead wood) or 3 (cleared). `Schad_agg` is cumulative since
  June 2017, so it means *ever damaged*; `Schadstufe` describes the current state and is not used.
- **Early symptoms** = `Schad_agg` 1. **Not assessed** = −1 (cloud mask) and −3 (stand too narrow);
  excluded from percentages but reported.
- **Two time frames:** *total loss since 2017* (each release is cumulative) and *new damage 2023–2025*
  (comparison of the three releases). Damage before September 2023 cannot be dated more precisely.
- **Species legend** (raster values, derived from the data in step 03b and checked visually):
  1 calamity area, 2 oak, 3 beech, 4 other hardwoods, 5 soft broadleaves (birch, alder …), 6 poplar,
  7 pine, 8 larch, 9 spruce, 10 Douglas fir.

## Limitations

- The data records conifer forest loss from **all causes** – bark beetle, drought, storm
  (Friederike, January 2018) and regular harvesting – and does not separate them.
- Remote-sensing classes are estimates; 4 % of the area is never assessed, and the 2024 release
  has 7,600 ha of cloud gaps.
- The species raster was made after most spruce died: cleared areas are their own class, and only
  55 % of the "spruce" pixels lie inside the provider's conifer mask.
- Percentages for municipalities with less than 100 ha of conifer forest are not meaningful and are
  flagged (`wenig_nadelwald = 1`).
- Hotspots of *new damage* use hectares per hexagon, so they partly reflect where spruce is still left.
- Elevation and tree species are linked (lowland conifers are mostly pine, upland mostly spruce), so part of
  the elevation effect reflects the species mix. GLO-30 is a surface model including the canopy; for 100 m
  bands this makes no practical difference.

## Errors found and fixed along the way

A selection from the vibe-coding log – each one was caught by checking results, not by the code itself.

| Problem | How it showed up | Fix |
|---|---|---|
| A script named `inspect.py` shadowed Python's `inspect` module | import error before any code ran | renamed to `inspect_data.py` (here: `03_inspect.py`) |
| `arcpy.management.AlterAliasName` does not exist | traceback after a long import | `arcpy.AlterAliasName` |
| `Schad_agg` is a double field; Tabulate Area needs integer zones | `ERROR 000864` | integer copy of the field in memory |
| `arcpy.sa.Combine` returns a temporary raster whose table can't be read | `'in_table' is not a table` | save the raster before reading its attribute table |
| `InList` returns NoData, not 0, for "not in list" | `Schadensjahr` raster completely empty; noticed via 0 rows in step 08 | plain comparisons (`r == 2 \| r == 3`) |
| District keys stored with a different format than assumed | district layer full of nulls in the attribute table | key normalisation + a "matched" check that warns |
| Species legend unknown (10 values, 9 named classes) | — | derived from the data: value 1 lies 100 % on cleared conifer areas |
| The downloaded elevation model had no coordinate system | `Undefined coordinate system` during reprojection | the script sets WGS 84 (EPSG:4326) when a file carries none |
